# Architecture

Workshop Arcade is a player-facing static catalog of HTML5 browser games designed to move cleanly from the current GitHub Pages preview to an owned-domain arcade. There is no backend — every game is a standalone HTML file in `websites/` that runs in the visitor's browser, and the catalog page (`index.html`) is plain HTML + inline CSS + inline ES2020. The player modal keeps browsing local with Save, Next, Random, More, Share, and fullscreen controls, while the footer Player data modal exposes counts and reset controls for browser-local state. This document explains how the pieces fit together so a new contributor (or AI agent) can find the right surface to change without reading every file.

The exact 100-game identity set is frozen until the user explicitly changes their mind. Existing games may be repaired, polished, rebalanced, or refactored, but additions, removals, renames, replacements, and unlisted game pages are blocked by `catalog-freeze.json` and `npm run test:catalog-freeze`.

## The manifest is the source of truth

Every generator and every validator reads from **[`websites/manifest.json`](websites/manifest.json)** — a JSON array of game entries shaped by [`schemas/manifest.schema.json`](schemas/manifest.schema.json). Editing the manifest is editing the catalog: daily and for-you player shelves, covers, sitemap, JSON-LD, OG share cards, feed entries, and the in-page `FALLBACK_GAMES` constant all derive from it. Canonical public URL settings live in [`scripts/site-config.mjs`](scripts/site-config.mjs), so sitemap/feed/OG/JSON-LD/meta can move from the current preview path to a root domain by setting `WORKSHOP_ARCADE_SITE_ORIGIN` and `WORKSHOP_ARCADE_SITE_BASE_PATH=/` before regeneration.

```
websites/manifest.json   ← single source of truth
        │
        ├── site-config.mjs      ──► canonical origin/base path for public metadata
        ├── inject-game-meta.mjs ──► websites/*.html (workshop-meta block + workshop-jsonld block)
        ├── build-sitemap.mjs    ──► sitemap.xml + robots.txt + index.html JSON-LD/root meta
        ├── build-feed.mjs       ──► feed.json
        ├── build-og-images.mjs  ──► covers/og/*.svg + covers/og-image.svg
        ├── catalog-csp.mjs      ──► index.html executable inline-script hash
        ├── validate-catalog.ps1 ──► (regenerates FALLBACK_GAMES inside index.html with -Fix)
        ├── smoke-games.mjs      ──► spawns Playwright across every entry
        ├── capture-games.mjs    ──► rendered-quality contact sheet
        ├── check-page-weight.mjs ──► fast static payload budget check
        └── audit-pagespeed.mjs  ──► strict perf/SEO budget audit
```

Per-game contract details (audio, render hooks, mobile layout) live in [`docs/game-contract.md`](docs/game-contract.md). The schema in [`schemas/manifest.schema.json`](schemas/manifest.schema.json) is wired into [`.vscode/settings.json`](.vscode/settings.json) so editors validate manifest entries inline.

## Generators

These scripts transform the manifest into the surfaces the catalog serves. All are byte-deterministic so the matching `test:*` validators can detect drift.

| Script | Produces | Triggered by | Validator |
|--------|----------|--------------|-----------|
| [`scripts/site-config.mjs`](scripts/site-config.mjs) | Canonical `SITE_URL` / path helpers consumed by SEO/social generators | env-driven helper | `test:owned-domain-readiness` + generator validators |
| [`scripts/inject-game-meta.mjs`](scripts/inject-game-meta.mjs) | Workshop-meta + workshop-jsonld blocks inside every `websites/*.html` | `npm run inject:meta` | `test:game-jsonld` |
| [`scripts/build-sitemap.mjs`](scripts/build-sitemap.mjs) | `sitemap.xml`, `robots.txt`, root canonical/OG URLs, and JSON-LD blocks in `index.html` | `npm run build:sitemap` | `test:seo` |
| [`scripts/build-feed.mjs`](scripts/build-feed.mjs) | `feed.json` (JSON Feed 1.1, newest-first) | `npm run build:feed` | `test:feed` |
| [`scripts/build-og-images.mjs`](scripts/build-og-images.mjs) | One 1200×630 `covers/og/<slug>.svg` per game | `npm run build:og-images` | `test:og-images` |
| [`scripts/catalog-csp.mjs`](scripts/catalog-csp.mjs) | Recomputes exact SHA-256 CSP sources for executable inline scripts in `index.html`; ignores inert JSON-LD | `npm run build:csp` or automatically after fallback regeneration | `test:csp` |
| [`scripts/validate-catalog.ps1`](scripts/validate-catalog.ps1) (with `-Fix`) | Rewrites `FALLBACK_GAMES` inside `index.html`, then refreshes its catalog CSP hash | `pwsh scripts/validate-catalog.ps1 -Fix` | catalog validator + `test:csp` |

## Validators (the fast gates)

`npm test` invokes [`scripts/run-fast-tests.mjs`](scripts/run-fast-tests.mjs), which auto-discovers every fast `test:*` npm script and runs them in sequence. Browser-backed probes (`test:games`, `test:pwa-runtime`, `test:runtime-storage`, `test:live-canvas-evidence`) stay explicit because they need Chromium/service worker support. Each gate locks in one concern.

| Concern | Validator(s) |
|---------|--------------|
| **Manifest contract** | `test:catalog-freeze` · `test:manifest-schema` · `test:tag-coverage` |
| **Catalog source of truth** | `validate-catalog.ps1` (no npm wrapper) |
| **Generator output mirrors manifest** | `test:seo` · `test:feed` · `test:og-images` · `test:game-jsonld` · `test:generated-surfaces` |
| **Catalog script authorization** | `test:csp` · exact inline-script SHA-256 sources generated by `npm run build:csp` |
| **Owned-domain launch config** | `test:owned-domain-readiness` · `test:owned-domain-rehearsal-contract` · `test:owned-domain-cutover-preflight-contract` |
| **Asset/runtime/perf contracts** | `test:cover-assets` · `test:storage-contract` · `test:runtime-storage` · `test:page-weight` · `test:pwa-install-budget` |
| **Catalog UI contracts** | `test:catalog-perf` · `test:workshop-feedback` · `test:deep-links` · `test:url-filters` · `test:random-game` · `test:keyboard-help` · `test:favorites` · `test:player-data-controls` · `test:player-session` · `test:sw-update-toast` |
| **Accessibility** | `test:a11y` · `test:a11y-polish` |
| **PWA + fallback pages** | `test:pwa` · `test:pwa-runtime` (includes bounded runtime-cache trim) · `test:fallback-pages` |
| **OSS hygiene** | `test:meta-files` · `test:security-workflows` · `test:github-security-settings` (explicit authenticated remote gate) · `test:current-head-workflows` (explicit authenticated remote gate) · `test:pages-artifact` · `test:contributor-onboarding` |
| **Tooling integrity** | `test:tools` · `test:test-aggregator` · `test:playwright-harness` · `test:publish-ready-contract` · `test:capture-recipes` · `test:docs` · `test:performance-baseline` · `test:validator-fixtures` |
| **Live game smoke** | `test:live-smoke-slugs` (fast fixture for gated-deployment touched-slug derivation and live-smoke provenance wiring) · `test:live-canvas-evidence` (local Playwright fixture for live-smoke canvas aggregation) · `test:games` (local Playwright, slow — run via `npm run test:games` or `npm run test:all`) · `test:live-pages` (validation-gated post-deploy smoke with auto-selected touched slugs plus explicit preview checks) |

The static page-weight gate also enforces launch headroom: the shell must retain at least a 20 KB / 5 request buffer below the Catalog budget, and named exception headroom requires Lexica, Idle Tycoon, Arcade Jump, and Brick Breaker to retain at least 10 KB / 1 request below their named budgets. `test:catalog-perf` keeps only the first visible cover row eager/high-priority and defers the remaining covers with the IntersectionObserver lazy path.

The tag coverage gate (`npm run test:tag-coverage`) requires each manifest tag to appear in at least 3 games and in `index.html` `CATEGORY_ORDER`, so category parity and filter-chip ordering cannot quietly drift. The [docs drift validator](scripts/check-docs-drift.mjs) (`test:docs`) keeps `README.md`, `CONTRIBUTING.md`, `docs/game-contract.md`, the PR/issue templates, and the workflow YAML all naming the same publish-ready command set, so contributor-facing docs can't quietly fall behind CI.

The game-smoke and render-capture sweeps share `scripts/playwright-harness.mjs`. They keep reusable desktop and mobile browser contexts, clear local/session storage before each game document, and allow one bounded retry only for `ERR_NO_BUFFER_SPACE` or `ERR_INSUFFICIENT_RESOURCES` after recreating the affected context. `npm run test:playwright-harness` locks in that policy. Both summaries expose `transportRetryCount` and `transportRetries`, so a recovered Windows resource transient remains visible in launch evidence.

## CI workflow structure

[`.github/workflows/validate-catalog.yml`](.github/workflows/validate-catalog.yml) starts with four jobs that run in parallel on every push and pull request:

1. **`catalog-docs-a11y`** — all the fast structural validators above, including the Pages artifact assembly guard, owned-domain readiness dry run, and `npm run test:live-smoke-slugs` touched-slug fixtures, in roughly the order generators → validators → a11y → tooling-meta. This is the job that gates merges on most catalog edits.
2. **`game-smoke`** — Playwright first proves the sandboxed storage fallback, service-worker offline behavior, and live-smoke canvas evidence aggregation in Chromium, then spawns the catalog page and opens every manifest game on desktop and mobile viewports, asserting no console errors and that filter chips / card tags behave correctly. The direct-game sweep reuses one isolated context per viewport and discloses any bounded Windows transport retry. Runs `npm run test:runtime-storage`, `npm run test:pwa-runtime`, `npm run test:live-canvas-evidence`, and `npm run test:games`, then uploads the source-identifying `game-smoke-summary` artifact from `test-results/smoke-games/<timestamp>/summary.json`.
3. **`performance-audit`** — boots the static server on port 4173 and runs `npm run audit:perf:ci` against it. For local publish checks, `npm run audit:perf:local` starts a disposable static server on an open loopback port, sets `WORKSHOP_ARCADE_URL`, runs the same strict audit, and cleans up the server. Strict mode fails if any page exceeds its publish budget (Catalog ≤ 200 KB / ≤ 18 requests; Lexica ≤ 165 KB / ≤ 4 requests; Idle Tycoon ≤ 170 KB / ≤ 4 requests; Arcade Jump ≤ 115 KB / ≤ 4 requests; Brick Breaker ≤ 125 KB / ≤ 4 requests; everything else ≤ 100 KB / ≤ 3 requests). The fast page-weight gate additionally enforces catalog shell headroom of 20 KB / 5 requests and named exception headroom of 10 KB / 1 request before the slower audit runs. The `performance-audit` artifact keeps `test-results/lighthouse-baseline/<timestamp>/summary.json` plus `report.md` with source revision provenance.
4. **`render-capture`** — runs `npm run capture:games:ci` to take desktop + mobile screenshots of every game and score them against a render-quality bar. The game sweep reuses one isolated context per viewport, while the contact sheet uses a separate context. Strict mode fails if any surface scores above 0. The `render-ranking` artifact includes `test-results/render-ranking/<timestamp>/summary.json`, `contact-sheet.html`, and `contact-sheet.png` with source revision provenance. The summary is fail-safe: unexpected early aborts still write status, error, expected/captured surface counts, last phase, retry evidence, and provenance, plus a partial contact sheet when any surface was captured.

On a `main` push or manual dispatch on `main`, three validation-gated jobs follow only after all four jobs above succeed:

5. **`pages-build` (`Build static artifact`)** — checks out the exact validated SHA, assembles the curated `_site` with `scripts/build-pages-artifact.mjs`, and uploads the Pages artifact. Pull requests and non-main refs skip this job.
6. **`pages-deploy` (`Deploy`)** — receives `pages: write` and `id-token: write` only at the job level, publishes to the `github-pages` environment, and exposes the deployed URL.
7. **`live-smoke` (`Live Pages smoke`)** — checks out the same SHA, derives touched slugs, retries `npm run test:live-pages` for propagation delays, and retains the source-identifying smoke artifact for 14 days. Per-ref concurrency cancels obsolete runs so an older main commit cannot publish after a newer push.

For one local launch-QA command, run `npm run test:publish-ready`. It executes the catalog validator, `npm test`, browser/runtime probes, `npm run test:games`, strict render capture, local performance audit, and `git diff --check` in order, then writes `test-results/publish-ready/<timestamp>/summary.json` and `test-results/publish-ready/<timestamp>/report.md`. Those files include source revision provenance: branch, commit, dirty state, manifest game count, and newest manifest slugs. After a source commit, run `npm run test:launch-evidence-refresh` from a clean worktree to refresh publish-ready plus live Pages evidence, verify it with `npm run test:launch-evidence-current`, and write combined evidence under `test-results/launch-evidence-refresh/<timestamp>/summary.json` plus `report.md`. The freshness check verifies the newest `test-results/publish-ready/<timestamp>/summary.json` and `test-results/live-pages-smoke/<timestamp>/summary.json` plus their reports identify the current clean HEAD. After the required GitHub Actions runs finish for that same commit, run `npm run test:current-head-workflows` to verify the top-level `Validate Catalog`, `CodeQL`, and `Security Surfaces` runs plus all seven Validate Catalog jobs completed with `success` for the current clean HEAD. Its `requiredValidateJobs`, `validateJobs`, and `deploymentGate` fields prove `Build static artifact` started after all four validations, followed by `Deploy` and `Live Pages smoke`, and the checker rejects any standalone `Deploy Pages` run. JSON/Markdown evidence is written under `test-results/current-head-workflows/<timestamp>/summary.json` plus `report.md`. The fast `test:publish-ready-contract` and `test:security-workflows` gates keep those slow/local/remote evidence commands wired without adding them to `npm test`.

For one local owned-domain rehearsal, run `npm run test:owned-domain-rehearsal`. It assembles the curated Pages artifact into `test-results/owned-domain-rehearsal/<timestamp>/site`, regenerates root-domain sitemap/feed/meta/JSON-LD/OG/security canonical surfaces inside that artifact only, serves it at `/`, then runs live smoke plus the strict performance audit. The runner passes `WORKSHOP_ARCADE_EXPECTED_ROOT`, `WORKSHOP_ARCADE_EXPECTED_SITE_URL`, and `WORKSHOP_ARCADE_EXPECTED_SECURITY_CANONICAL` so `npm run test:live-pages` keeps content-hash checks enabled while comparing against the generated artifact. It writes `test-results/owned-domain-rehearsal/<timestamp>/summary.json` and `test-results/owned-domain-rehearsal/<timestamp>/report.md` with source revision provenance; `test:owned-domain-rehearsal-contract` keeps that slow path wired without adding it to `npm test`.

For one local owned-domain cutover preflight, run `npm run test:owned-domain-cutover-preflight`. It defaults to `WORKSHOP_ARCADE_CUSTOM_DOMAIN=arcade.example.test`, runs the rehearsal with `WORKSHOP_ARCADE_SITE_BASE_PATH=/`, and writes `test-results/owned-domain-cutover-preflight/<timestamp>/summary.json` plus `test-results/owned-domain-cutover-preflight/<timestamp>/report.md` without committing a fake domain. The evidence starts with source revision provenance before any domain-specific checks. With a real `WORKSHOP_ARCADE_CUSTOM_DOMAIN`, it validates the hostname, queries GitHub Pages settings read-only, and can become strict with `WORKSHOP_ARCADE_CHECK_DNS=1` and `WORKSHOP_ARCADE_REQUIRE_PAGES_CNAME=1`. GitHub's current Actions-based Pages publishing does not require a tracked `CNAME`; the custom domain belongs in Pages settings and DNS.

After a `main` push, the validation-gated Pages jobs inside [`.github/workflows/validate-catalog.yml`](.github/workflows/validate-catalog.yml) assemble the preview `_site` artifact with `scripts/build-pages-artifact.mjs` from the static app, public docs/tooling surfaces, and `.well-known/security.txt`, publish it with the GitHub Pages Actions flow instead of the legacy branch-root build, derive touched game slugs from the push diff with `scripts/derive-live-smoke-slugs.mjs`, then run `npm run test:live-pages` against the deployed Pages URL with a short retry loop for propagation delays. A manual dispatch on `main` follows the same validation chain; there is no unvalidated redeploy path. This is maintenance infrastructure for the current preview; the product target remains an owned-domain arcade using the same static artifact and canonical URL config. `npm run test:owned-domain-readiness` dry-runs the root-domain canonical config in memory so sitemap/feed/root meta/game JSON-LD output can be proven before a final domain is chosen. Validate Catalog uploads source-identifying `game-smoke-summary`, `performance-audit`, `render-ranking`, and `live-pages-smoke` artifacts so failed validation or deployment runs retain evidence with source revision provenance. `npm run test:current-head-workflows` is the post-push authenticated remote check for the current clean HEAD: it queries `gh run list` and `gh run view`, then writes `test-results/current-head-workflows/<timestamp>/summary.json` plus `report.md` proving the three top-level workflows and validation-gated job order are complete and successful for the same commit. `npm run test:pages-artifact` builds and verifies that same artifact policy locally so hidden public paths and internal directory exclusions are checked before deployment. `npm run test:live-smoke-slugs` locally guards the direct game, cover, OG cover, shared-script, fallback, de-duping, `$GITHUB_ENV` slug-selection behavior, and live-smoke provenance wiring before deployment. `npm run test:live-canvas-evidence` locally guards the live-smoke canvas aggregation logic before deployment, while the live smoke checks the deployed catalog, manifest, feed, sitemap, PWA/fallback surfaces, `.well-known/security.txt`, selected direct game pages, browser errors, mobile overflow, rendered screenshots/diagnostics, canvas nonblank evidence, and verifies the catalog does not call the GitHub API during startup. It also compares deployed shell/catalog SHA-256 content hashes (`index.html`, `websites/manifest.json`, `feed.json`, `sitemap.xml`, `app.webmanifest`, `offline.html`, `404.html`, `robots.txt`, and `.well-known/security.txt`), deployed game HTML SHA-256 content hashes, and the deployed `sw.js` `SHELL_REVISION` with local files so a Pages smoke proves the deployed shell and touched pages match the branch being verified; set `WORKSHOP_ARCADE_EXPECTED_ROOT` for a generated artifact root, `WORKSHOP_ARCADE_EXPECTED_SITE_URL` for its public canonical root, `WORKSHOP_ARCADE_EXPECTED_SECURITY_CANONICAL` for its RFC 9116 canonical URL, `WORKSHOP_ARCADE_EXPECTED_SW_REVISION` for an intentional alternate revision, `WORKSHOP_ARCADE_SKIP_SW_REVISION=1` only for historical deploy checks, or `WORKSHOP_ARCADE_SKIP_CONTENT_HASH=1` only for intentional historical/preview content checks. Set `WORKSHOP_ARCADE_URL` for a preview deployment and `WORKSHOP_ARCADE_LIVE_SLUGS` or `WORKSHOP_ARCADE_TOUCHED_SLUGS` for the game pages touched by the release; `WORKSHOP_ARCADE_REQUIRE_LIVE_SLUGS=1` fails release verification that forgets explicit slugs. Without a slug override, including non-push/manual workflow runs or commits with no game-related file paths, the smoke checks the three newest manifest entries. Each run writes `test-results/live-pages-smoke/<timestamp>/summary.json` and `test-results/live-pages-smoke/<timestamp>/report.md` with source revision provenance for handoff evidence.

Two additional workflows and Dependabot live alongside:

- [`.github/workflows/codeql.yml`](.github/workflows/codeql.yml) — CodeQL `javascript-typescript` analysis with the `security-extended` query pack on every push/PR plus a Monday cron.
- [`.github/workflows/security-surfaces.yml`](.github/workflows/security-surfaces.yml) — Security Surfaces drift check for GitHub-native vulnerability alerts, Dependabot security updates, private vulnerability reporting, secret scanning, secret scanning push protection, and open security alert backlogs via `npm run test:github-security-settings` on push, weekly, and manual dispatch. The workflow uses `SECURITY_SURFACES_TOKEN` as the strict remote gate token when configured; otherwise it records the default `GITHUB_TOKEN` API limitation as an Actions warning and leaves the local command strict.
- [`.github/dependabot.yml`](.github/dependabot.yml) — weekly Monday npm + github-actions update PRs, scoped commit prefixes (`deps:` / `ci:`), and a `playwright` group so the `@playwright/*` family lands in one PR.

All external workflow actions use full 40-character commit SHAs rather than movable tags. Same-line `vX.Y.Z` comments retain release readability and let Dependabot update the immutable pins. `npm run test:security-workflows` scans every workflow, rejecting tags, branches, short SHAs, missing release comments, unsupported majors, and inconsistent releases for the same action repository.

## Why game pages stay hand-authored, not templated

A build-time shared-fragment / templating system for the 100 game pages was evaluated and **rejected** (2026-07-02). The apparent cross-game "duplication" is overwhelmingly intentional per-game variation, not extractable shared content. Measured across the catalog: the ambient radial backdrop exists in only 46 games as 30+ near-unique variants (the most common exact string is shared by just 12); the `.pill` HUD rule has a long tail of per-game padding/width tweaks (top variant 13 games); every `:root` palette (37 games) is a unique color identity; and each `render_game_to_text()` body returns game-specific state. The genuinely shared surfaces are *already* extracted: the per-game meta + JSON-LD block (~2.5 KB/game) is generated in place by [`scripts/inject-game-meta.mjs`](scripts/inject-game-meta.mjs) through `<!-- workshop-meta -->` markers, and the storage-bridge shim plus the `prefers-reduced-motion` reset live once in [`websites/workshop-runtime.js`](websites/workshop-runtime.js), loaded by all 100 pages. Forcing the remaining superficially-similar CSS into shared blocks would homogenize dozens of games' intentional visual identity (a `capture:games:ci` regression), save little, and add a build + injection subsystem, a new drift gate, and per-game migration risk for near-zero ROI. Self-contained, hand-authored pages remain the deliberate choice; extract shared code only when it is genuinely byte-identical across games (as the meta block and runtime shim are).

## Content freeze and future game additions

Do not use the recipe below while `catalog-freeze.json` is active. It is retained only so the integration procedure is not lost if the user explicitly lifts or changes the freeze. That future pass must update the policy, agent runbook, contributor docs, and Workshop feedback flow before creating files.

After the freeze is explicitly lifted, the end-to-end recipe is:

1. **Author the game file** at `websites/<slug>.html` — a single self-contained HTML page that follows [`docs/game-contract.md`](docs/game-contract.md) (canvas with `aria-label`, persisted sound toggle, `render_game_to_text()` + `advanceTime(ms)` diagnostics for the smoke harness, mobile layout, etc.).
2. **Draw a 640×360 cover** at `covers/<slug>.svg` (or another supported format) — reuse the catalog's dark gradient palette so the catalog grid stays cohesive.
3. **Add a manifest entry** to `websites/manifest.json` with `id` / `title` / `subtitle` / `tags` / `slug` / `url` / `cover` / `addedAt` / `popularity`. The schema in `schemas/manifest.schema.json` will validate the entry inline in any JSON-Schema-aware editor.
4. **Regenerate derived surfaces**:

   ```powershell
   pwsh scripts/validate-catalog.ps1 -Fix    # refreshes FALLBACK_GAMES inside index.html
   npm run inject:meta                       # workshop-meta + workshop-jsonld per game
   npm run build:sitemap                     # sitemap.xml + index.html ItemList
   npm run build:feed                        # feed.json
   npm run build:og-images                   # 1200x630 share card
   ```

5. **Add a capture recipe** in `scripts/capture-games.mjs` so the render-quality harness knows how to interact with the new game (start, take a screenshot at an interesting moment).
6. **Run `npm test`** — every fast gate should pass.
7. **Run `npm run test:games`** to confirm the Playwright smoke suite is happy with the new entry, `npm run test:publish-ready` before publishing a larger launch-QA pass, or `npm run test:owned-domain-cutover-preflight` before final custom-domain work.
8. **Commit and publish.** GitHub Actions runs the four validation jobs plus CodeQL; once all four validations pass on `main`, the gated build, deploy, and live-smoke jobs publish and verify the curated static artifact. For owned-domain launch, set the final canonical URL config, configure the custom domain in Pages settings and DNS, regenerate metadata, deploy the same artifact to the domain host, and run `npm run test:live-pages` with `WORKSHOP_ARCADE_URL` pointed at the owned domain.
